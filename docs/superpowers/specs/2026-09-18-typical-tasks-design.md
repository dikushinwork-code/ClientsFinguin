# Типовые задачи в дорожной карте — дизайн

Дата: 2026-09-18. Макет, утверждённый с правками: https://claude.ai/artifact/8HWtLxKPjK7XLQaYpNJDcw

## Зачем

У финансового директора (ФД) при появлении нового клиента возникают одни и те же задачи:
внедрить ДДС, построить финансовую модель и т. п. Сейчас каждую приходится заводить в
дорожной карте вручную. Нужна кнопка «Типовая задача»: ФД выбирает шаблон из реестра,
указывает дату старта и ответственного, а приложение само разворачивает надзадачу,
подзадачи-спринты по нормативам, контрольные точки и пояснения к ним.

Реестр шаблонов хранится в `docs/typical-tasks.md` (формат описан в самом файле). Это
источник правды для шаблонов; приложение его читает, а не дублирует.

## Пользовательский сценарий

1. В шапке дорожной карты рядом с «Новая задача» появляется кнопка «Типовая задача».
2. **Шаг 1 — выбор шаблона.** Компактный список: код, название, «N нед. · M точек».
   Сверху поле поиска по коду и названию. Если задача с таким кодом уже есть у клиента,
   строка показывает «уже в карте с ДД.ММ», но выбор не блокируется. Никаких пояснений о
   происхождении шаблонов и путях к файлам в интерфейсе нет.
3. **Шаг 2 — параметры.** Дата начала (по умолчанию ближайший понедельник), ответственный
   (тот же компонент выбора людей, что и в обычной задаче). Если выбран не понедельник,
   под полем подсказка «Выбран четверг. Спринты будут считаться с этого дня» и кнопка
   «Сдвинуть на понедельник ДД.ММ». Если у шаблона есть предпосылка или ритм встреч
   (строка `**Ключ:** текст` в файле), она показывается одной серой строкой под полями —
   это предметная подсказка ФД, а не техническая. Ниже предпросмотр: по строке на спринт
   (неделя, даты, код, название, число точек) и итог: старт, дедлайн с днём недели,
   всего точек.
   Кнопки: «Другой шаблон» (назад), «Отмена», «Добавить в карту».
4. После добавления окно закрывается, новые строки появляются в таблице и на Ганте,
   шкала прокручивается к дате старта, показывается уведомление.

## Как это выглядит в карте

- Надзадача: чип с кодом шаблона (тёмный, «ДДС») перед названием, счётчик подзадач,
  сводный прогресс по точкам «5/16».
- Подзадача-спринт: чип с кодом спринта («ДДС-1»), прогресс «3/9» с кольцевым индикатором.
- Полоски Ганта не меняются, кроме подсказки при наведении (даты и прогресс по точкам).
- Всё остальное (фильтры, базовый план, сворачивание, статусы, просрочка) работает как для
  обычных задач: типовая задача — это обычные `Task` с дополнительными полями.

## Карточки

**Карточка подзадачи-спринта** (открывается по строке или полоске):

- Заголовок «ДДС-1. Название», подзаголовок «Типовая задача ДДС · спринт 1 из 3 · неделя
  ДД.ММ — ДД.ММ».
- Поля: название подзадачи (редактируется), ответственный, статус, дата начала, дедлайн.
- Блок «Контрольные точки»: счётчик «3 из 9» и полоса прогресса. Точки сгруппированы, как в
  шаблоне (например, ФМ-1а / ФМ-1б с «Проверочным результатом»). Строка точки: чекбокс,
  короткий код («1.5»), текст, курсивная ремарка в скобках, кнопка «i» (если есть
  пояснение) и карандаш. Контрольные ворота (жирные в шаблоне) выделены жирным.
- «i» раскрывает пояснение под строкой (по клику, не по наведению).
- Карандаш переводит строку в режим правки: поле текста, поле пояснения, кнопки
  «Удалить», «Отмена», «Готово». Пустой текст при «Готово» удаляет точку.
- Внизу списка кнопка «Добавить контрольную точку»: новая точка добавляется в последнюю
  группу с очередным номером (`ДДС-1.10`) и сразу открывается на правку.
- Когда все точки отмечены, а статус не «Завершено», показывается плашка «Все контрольные
  точки отмечены — спринт можно закрывать» с кнопкой «Отметить завершённым» (меняет
  статус в форме, сохранение — по общей кнопке).
- Комментарии — как у обычной задачи. Кнопки «Удалить», «Отмена», «Сохранить».
- Все правки применяются только по «Сохранить» (черновик, как в остальных диалогах).

**Карточка надзадачи типовой задачи**:

- Заголовок «ДДС. Название», подзаголовок «Типовая задача · 3 спринта · даты · точек 5 из 16».
- Поля: название, ответственный, статус, даты. Статус надзадачи ФД выставляет сам, как у
  обычных надзадач (автоматики нет).
- Блок «Спринты»: по строке на подзадачу (код, название, даты, мини-прогресс), клик
  открывает карточку спринта.
- Комментарии, «Удалить» (удаляет вместе с подзадачами, как сейчас), «Сохранить».

**Обычная задача** не меняется.

## Модель данных

Типовая задача — это обычные записи `Task`, поэтому Гант, фильтры, базовый план и
хранилище работают без изменений. Добавляются необязательные поля:

```ts
export interface Checkpoint {
  code: string;        // «ДДС-1.5», стабильный, используется как ключ
  title: string;
  aside: string;       // ремарка в скобках, может быть пустой
  gate: boolean;       // контрольные ворота (жирный пункт в шаблоне)
  noteTitle: string;   // заголовок пояснения, пустой если пояснения нет
  note: string;        // текст пояснения
  done: boolean;
}

export interface CheckpointGroup {
  title: string;       // «ФМ-1а. Сбор данных…» или пустая строка
  result: string;      // «Проверочный результат», может быть пустым
  items: Checkpoint[];
}

export interface Task {
  // ...существующие поля
  template?: {
    code: string;      // код шаблона «ДДС»
    subCode?: string;  // код спринта «ДДС-1», только у подзадач
    week?: number;     // номер спринта, только у подзадач
  };
  groups?: CheckpointGroup[]; // только у подзадач типовой задачи
}
```

Контрольные точки и пояснения **копируются** в задачу при создании и дальше принадлежат
клиенту: ФД может менять текст, пояснение, добавлять и удалять точки. Правка шаблона в
`docs/typical-tasks.md` влияет только на задачи, создаваемые после неё.

Число спринтов надзадачи вычисляется по подзадачам с `template.subCode`, отдельно не хранится.

## Шаблоны: чтение из markdown

Модуль `lib/typical-tasks.ts`:

```ts
export interface TypicalTaskTemplate {
  code: string; title: string; weeks: number; premise: string;
  subtasks: { code: string; title: string; groups: CheckpointGroup[] }[]; // items без done
}
export function parseTypicalTasks(markdown: string): TypicalTaskTemplate[];
export function expandTemplate(tpl, startDate, assignee): Task[]; // надзадача + подзадачи
```

Правила разбора (по соглашениям файла):

- Задача начинается с `# КОД. Название`; `**Длительность:** N недель`; `**Предпосылка:**`
  или другая строка вида `**Ключ:** текст` попадает в `premise`.
- Подзадача — `## КОД-N. Название`; группа внутри — `### КОД-Nа. Название`; строка
  `**Проверочный результат:** …` относится к текущей группе (или к подзадаче, если групп
  нет — тогда создаётся одна безымянная группа).
- Пункт — `- [ ] \`КОД-N.M\` Текст`; продолжение на следующих строках с отступом
  склеивается через пробел; `*(курсив в скобках)*` в конце становится `aside`;
  `**жирный**` целиком — `gate`; `(i)` в конце убирается и означает наличие пояснения.
- Пояснения — раздел `## Заметки к задаче КОД`: блок `**\`КОД-N.M\` Заголовок**` и абзац
  текста до пустой строки. Привязываются к пункту по коду.
- Раздел «Шаблон новой типовой задачи» (внутри ```-блока) и всё до первого `# КОД.`
  игнорируются. Реестр-таблица в начале файла не используется как источник.
- Ошибка формата (пункт без кода, пояснение к несуществующему коду, длительность не число)
  — исключение с номером строки; сборка должна упасть, а не выдать кривой шаблон.

Файл читается в `app/page.tsx` (`fs.readFile` из корня проекта) и передаётся в
`Dashboard` пропом `templates`. Страница полностью статическая, поэтому чтение происходит
при сборке, а трассировка файлов для Vercel не нужна (документация Next: статические
страницы `outputFileTracingIncludes` не затрагивает). Ошибка формата валит сборку.

## Разворачивание по нормативам

- Спринт = 7 дней. Подзадача k (с 1) получает `startDate = start + 7·(k−1)`,
  `endDate = start + 7·(k−1) + 6`. Надзадача: от `start` до конца последней подзадачи.
- Праздники и выходные не учитываются.
- Статус всех созданных задач «Не начато», ответственный — выбранный на шаге 2, у всех.
- Порядок в таблице: новые записи добавляются в конец `tasks` (надзадача, затем подзадачи).

## Тестирование

- Юнит-тесты парсера: полный файл разбирается в 2 шаблона с ожидаемым числом подзадач,
  групп, точек, пояснений; `ФМ-1.22` — `gate` и с пояснением; `ДДС-1.4` — `aside`;
  многострочный пункт `ФМ-1.2` склеен; битый файл даёт ошибку с номером строки.
- Юнит-тесты `expandTemplate`: даты спринтов и надзадачи при старте в понедельник и не в
  понедельник; коды и `week` у подзадач; точки скопированы с `done: false`.
- Ручная проверка по макету: добавить ДДС, открыть спринт, отметить точки, добавить и
  удалить точку, изменить пояснение, сохранить, перезагрузить страницу — изменения
  сохранены; удалить надзадачу — подзадачи удалены; `pnpm lint` и `pnpm build` проходят.

В проекте пока нет тест-раннера: добавить `vitest` в devDependencies и скрипт `pnpm test`.

## Вне объёма

- Обновление уже созданных задач при изменении шаблона.
- Редактирование шаблонов из интерфейса.
- Фильтр «только типовые» в шапке.
- Учёт праздников при расчёте спринтов.
