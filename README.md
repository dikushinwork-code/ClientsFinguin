# Дорожная карта финансового директора

Одностраничный рабочий кабинет для контроля внедрения управленческой отчётности у одного клиента.

## Возможности

- диаграмма Ганта с надзадачами, недельными спринтами, сроками, ответственными и статусами;
- базовый план: выбор даты, на которую смотрим, и штриховка сдвинувшихся сроков прямо на диаграмме;
- управленческие решения с поиском, фильтрами, приоритетами и комментариями;
- календарь встреч с плановыми и фактическими датами;
- повторяющиеся встречи одной серией: удалить или изменить можно только выбранную встречу, её и все последующие либо всю серию;
- регулярные задачи с подэтапами, недельной, месячной или квартальной периодичностью;
- прокручиваемый план-факт по месяцам, автоматические статусы и примечания к отклонениям;
- добавление, редактирование и удаление данных прямо на странице;
- автоматическое сохранение без авторизации;
- типовые задачи: шаблон из справочника разворачивается в надзадачу, недельные спринты и чек-лист контрольных точек с пояснениями.
- четыре индикатора сверху: план работ на 2 месяца, недельные спринты в срок, закрытие прошлого месяца (по регулярным задачам или ручной отметкой), следующая встреча;
- причина обязательна при переносе срока спринта; история переносов хранится в карточке и видна на диаграмме;
- журнал запросов клиенту у контрольных точек: «ждём клиента · 3 запроса»; даты запросов можно отмечать задним числом, исправлять и удалять;
- надзадачи свёрнуты по умолчанию и показывают сводку: просрочено, перенесено, ждём клиента;
- вкладка «Неделя»: что сделано, какие были переносы и почему, что запланировано на следующую неделю.
- вкладка «Руководителю» под паролем: еженедельный чек-лист проверки дорожной карты с динамикой за 8 недель и комментариями.

## Публикация в Vercel

1. Импортируйте проект в Vercel как приложение Next.js.
2. Откройте вкладку Storage → Connect Database → Neon (можно оставить префикс переменной по умолчанию, например `DATABASE`) и подключите базу ко всем нужным окружениям.
3. Выполните повторный Deploy.

Приложение само находит рабочую переменную с адресом Postgres (`DATABASE_URL`, `POSTGRES_URL` или любую другую, которую создаст интеграция) — вручную ничего переименовывать не нужно. При первом обращении оно автоматически создаст таблицу `dashboard_state` и заполнит её стартовыми данными.

Без базы данных локальная разработка использует файл `work/dashboard-data.json`; на Vercel постоянное хранение обязательно требует подключённой базы — без неё сохранение вернёт понятную ошибку вместо тихого падения.

## Базовый план

Кнопка «Базовый план» над диаграммой открывает выбор даты: приложение показывает ближайший снимок сроков на эту дату или раньше. Задачи с неизменившимися сроками выглядят как обычно; расхождение помечается штриховкой — поверх полоски, если срок вырос, и за её краем, если сократился.

Снимки снимаются автоматически: при первом за сутки сохранении сервер откладывает сроки задач в том виде, в каком они были до правки. Дни без изменений новых снимков не создают, хранится последние 180 записей. История принадлежит серверу — клиент её не перезаписывает.

Проверить состояние подключения можно на `/api/health` — там видно, какая переменная найдена, к какому хосту идёт подключение и отвечает ли база.

## Повторяющиеся встречи

При создании встречи можно выбрать повторение — каждую неделю, месяц или квартал. Приложение создаёт отдельные встречи на 12 месяцев вперёд и связывает их в серию, поэтому у каждой остаются собственные статус, фактическая дата, итоги и комментарии.

Если регулярная встреча отвалилась, открывать каждую копию не нужно: в карточке встречи из серии кнопки «Удалить» и «Сохранить» спрашивают охват — **только эту встречу**, **эту и все последующие** или **всю серию**. Диалог показывает, сколько встреч затронет каждый вариант.

Правка по серии обновляет тему, время, участников и повестку; перенос даты сдвигает выбранные встречи на столько же дней. Статусы, итоги и комментарии остаются у каждой встречи своими. Если правка касается только одной встречи (например, её отметили проведённой), вопрос об охвате не задаётся.

Встречи, созданные до появления серий, подхватываются автоматически: сервер один раз связывает их по совпадающим теме, времени и составу участников при ровном шаге дат.

## Типовые задачи

Кнопка «Типовая задача» над диаграммой открывает реестр шаблонов. После выбора шаблона, даты старта и ответственного приложение создаёт надзадачу и по одному спринту на каждую неделю норматива; в каждом спринте — чек-лист контрольных точек с пояснениями для финансового директора. Точки можно отмечать, править, добавлять и удалять — они принадлежат клиенту, а не шаблону.

Справочник шаблонов — файл `docs/typical-tasks.md`, формат описан в его начале. Файл читается при сборке; ошибка формата (пункт без кода, пояснение к несуществующему пункту, число недель не равно числу спринтов) останавливает сборку с указанием строки. Правка шаблона влияет только на задачи, создаваемые после неё.

## Контроль по неделям

Отметка контрольной точки запоминает день, перевод задачи в «Завершено» — день завершения.
Из этих дат, истории переносов и сроков собирается вкладка «Неделя»: что закрыто за неделю,
какие сроки перенесены и по какой причине, у каких спринтов срок прошёл без нового, что
запланировано на следующую неделю. Прошлые недели можно листать: сроки на их конец
восстанавливаются по истории переносов. Неделя без закрытых пунктов и без переносов
помечается как «Неделя без движения».

Перенос срока спринта на более позднюю дату требует причину: клиент не дал данные, не успели,
сменился приоритет, технический блокер или другое (с комментарием). Можно указать пункт
чек-листа, который держит.

Плитка «Закрытие месяца» показывает закрытие прошлого месяца. Месяц закрыт, когда выполнены
все ежемесячные регулярные задачи, которые его закрывают: даты с 1-го по 15-е закрывают
предыдущий месяц, с 16-го — текущий. По клику на плитку месяц можно отметить закрытым
вручную с любой датой — ручная отметка главнее расчёта по задачам и снимается там же.

## Вкладка «Руководителю»

Третий пункт в переключателе страниц. Руководитель группы раз в неделю проверяет, как финдир
ведёт дорожную карту, и отмечает шесть пунктов чек-листа: встречи, план спринтов на 2 месяца,
итоги недели, работа с клиентом, регулярные задачи, отчётность и решения. Подробные критерии
спрятаны в подсказки ⓘ.

Матрица показывает 8 последних недель; последняя — прошлая полная неделя «к проверке».
Клик по клетке: пусто → ✓ → ✗ → пусто. Под матрицей — комментарии выбранной недели: что
делаем по пунктам с ✗ и ответы на вопросы к финдиру, если карта сама на них не ответила.

Вкладка закрыта общим паролем: по умолчанию `admin`, сменить — переменной окружения
`CONTROL_PASSWORD` в Vercel → Settings → Environment Variables и redeploy. Смена пароля
разлогинивает всех. Отметки хранятся отдельно от дорожной карты: таблица `control_state`
в базе, локально — файл `work/control-data.json`.

## Локальный запуск

```bash
pnpm install
pnpm up
```

Приложение открывается на http://127.0.0.1:3015. Также можно запустить `npm run up`.
Если порт занят другим проектом: `npm run up -- --port 3016` (укажите свободный порт).

Проверка перед публикацией:

```bash
pnpm test
pnpm lint
pnpm build
```

Страница намеренно не содержит авторизации: любой посетитель ссылки может изменять данные. Исключение — вкладка «Руководителю», она закрыта паролем.
